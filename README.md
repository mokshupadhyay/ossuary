# Ossuary 🦴

> Poltergeist-proof money. A Kiro skeleton for payment code that survives duplicate webhooks, double-taps, retries and crashes.

**Hackathon:** Kiroween 2026 · **Category:** Skeleton Crew · **Demo video:** _todo_ · **Live apps:** [below](#live-apps) (not yet deployed)

## The problem
AI writes payment code that works in the demo and loses money in production. A webhook arrives twice and a user is paid twice. A double-tap charges twice. A crash mid-transfer leaves money nowhere.

## What's in the skeleton
| Folder | What it is |
|---|---|
| `packages/core` | Double-entry ledger, idempotency keys, signed webhooks, outbox, the poltergeist engine and drift meter |
| `power/` | The Ossuary Kiro power: steering, skills and an MCP server |
| `apps/the-tontine` | A savings circle built on the skeleton |
| `apps/haunted-tip-jar` | Streamer tips, built through the power |

## How Kiro was used
Full write-up, with the commands behind every number: [`docs/KIRO_USAGE.md`](docs/KIRO_USAGE.md).

- **IDE, then the CLI headless.** The first spec, [`ledger-core`](.kiro/specs/ledger-core), was generated, revised and run in the Kiro IDE: 44 task executions are recorded in its `tasks.meta.json`. The later sessions ran `kiro-cli chat --no-interactive`, one instruction file each, under `docs/session-*.md`: the power, both apps and the polish passes. The Vibe Pay twin also came from one headless CLI run. Kiro Web and Crew were not used.
- **Specs.** Six specs in [`.kiro/specs`](.kiro/specs), with 66 requirements and 181 tasks, all ticked. The vibe-coded comparison is the twin: 185 lines from a one-paragraph prompt. With seed 7 and 2,000 events, Ossuary blocks all 728 ghosts with 0 drift. The twin lets 526 through and drifts 55,504.318662 USDC.
- **Steering.** Six files in [`.kiro/steering`](.kiro/steering): four always included, two by file match.
- **Hooks.** Four IDE hooks in [`.kiro/hooks`](.kiro/hooks): a money guard on save, a test run after each task, a webhook-handler check, and a "Summon the poltergeist" button.
- **Custom agent.** [`money-auditor`](.kiro/agents/money-auditor.json) is a read-only reviewer that ends with `VERDICT: PASS` or `FAIL`. The PR workflow `money-audit.yml` runs it, but that workflow has never run.
- **MCP and the power.** [`power/`](power) bundles the steering, 3 skills and an MCP server with 3 tools: `ossuary_check_money_code`, `ossuary_run_poltergeist` and `ossuary_explain_rule`. It has 227 tests.
- **Property-based testing.** 22 fast-check property files across core, the apps and the power. Each one is listed in the write-up with the mutations it was checked against, including where no mutation was recorded.

Known limits: CI has not run on GitHub; the IDE "install power from folder" route is unconfirmed; the twin is less naive than expected ([`packages/twin/PRODUCED.md`](packages/twin/PRODUCED.md)); and PGlite logs one harmless `ErrnoError` in the browser.

## Correctness properties
Every property is a fast-check test on an in-process Postgres (pglite). Each one was shown to **fail** against a deliberate break before it was accepted (mutation-checked).
| Property | Test |
|---|---|
| Ledger always sums to zero | `packages/core/tests/property/entrySum.property.ts` |
| One effect per idempotency key | `packages/core/tests/property/idempotency.property.ts` |
| Replayed / out-of-order webhooks change nothing | `packages/core/tests/property/webhookOrder.property.ts`, `staleTimestamp.property.ts` |
| Refunds never exceed captured | `packages/core/tests/property/refundCap.property.ts` |
| Crash at any step is all-or-nothing | `packages/core/tests/property/atomicity.property.ts`, `outboxDurability.property.ts` |
| The same seed gives the same storm and the same report | `packages/core/tests/property/stormDeterminism.property.ts` |
| Ossuary never drifts under the poltergeist (any seed, up to 2,000 events) | `packages/core/tests/property/ossuaryZeroDrift.property.ts` |
| The Vibe Pay twin visibly drifts, and the report names the fault | `packages/core/tests/property/twinDrifts.property.ts` |
| Every blocked ghost maps to a fault in the catalog | `packages/core/tests/property/blockedGhosts.property.ts` |

Run them: `pnpm --filter core test` (348 tests, about 45–75 seconds).

## CI
[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on every push and pull request. It installs with `pnpm install --frozen-lockfile` (and the same for `power/mcp`, which has its own lockfile), then runs core's tests and type check, each app's tests, type check and build, and the power's tests, type check and build. Playwright e2e runs in a separate job that installs Chromium. **This workflow has not yet run on GitHub.** It has only been checked locally: the YAML parses, its structure is valid, every command it calls exists, and both frozen installs succeed.

Summon the poltergeist: `pnpm poltergeist --seed 7 --events 2000 --target ossuary|twin [--json]`. The twin in `packages/twin` was generated by a coding agent from a one-paragraph prompt and is never edited; `packages/twin/PRODUCED.md` says how, and what it does differently from what we expected.

## Live apps
Both apps are static sites: Postgres runs in the browser (PGlite) and nothing calls a server. Each has a `vercel.json` with the monorepo install command (`cd ../.. && pnpm install --frozen-lockfile`), its build command and `dist` as the output directory. To deploy one, set the Vercel project's root directory to the app folder. Neither app has been deployed yet.
